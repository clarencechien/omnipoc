## 1. 最後的做法（一句話版）

**先用 Nano Banana 把每一幕的參考圖做到「臉、服裝、場景、色調」都對，再拿它當 Omni 影片的第一格（必要時再給最後一格），生成後用 3.8 Flash 看兩次找穿幫、人工確認，只剪乾淨的片段；配樂與字幕在放大到 1080p 之後才加。**

```
角色設定（playbill 定案人物）
  └─ 便服三視圖 ＋ 2K 臉部設定圖（正面／3/4／側面）
地點照片（Commons CC ＋ Clarence 提供）
  └─ Nano Banana 2 轉繪成陶土繪本風 → 每幕一張參考圖
       └─ 服裝檢查 ＋ 臉部檢查（框臉放大比對）→ 不過就「只修臉」局部重繪
Omni 1.2 影片：第一格＝參考圖；運鏡要精準時加最後一格
  └─ 複雜鏡頭先 360p 草稿 → 720p 定稿
       └─ 3.8 Flash 看整支影片 ×2 → 兩次都標出的才算 → 人工逐格確認
剪接表（只取乾淨秒數）→ 720p 試剪
  └─ Real-ESRGAN（Modal T4）放大乾淨片段 → 在 1080p 上加歌詞字幕與歌曲
       └─ 輸出 yuv420p／H.264 High
```

## 3. Lessons Learned

### 3.1 分鏡與溝通

1. **分鏡要結構化，不要只有表格。** 一份 YAML（鏡頭、秒數、參考圖、prompt、旁白、字幕）加產生器，讓「改一處，文件、prompt 檔、預算一起更新」。改了 9 個版本都沒有對不上的問題。
2. **在地事實要問本人或查證，不要猜。** 這次被糾正的：四號公園沒有水池（改圖書館前）、塔尖不要、雲林是透天不是三合院、母校是雲科大、劇場是 PLAYground 南村劇場看 LPC、YouBike 要各騎一台且一前一後、大學是車衣不是制服。模型認不得的地方一律給照片。
3. **運鏡寫得越複雜越容易亂。** 單支 15 秒「360° 環繞」只繞了 90°、後半亂掉；拆成兩段 8 秒、頭尾都給圖才成功。後來把蛋糕店、四四南村、YouBike 都簡化成固定機位或單純平移。
4. **人物不開口，台詞交給旁白或歌聲。** 陶土公仔閉嘴微笑和 playbill 風格一致，也完全避開對嘴問題。MV 直接用歌當旁白，效果最好。

### 3.2 參考圖與一致性

5. **參考圖只是引導，鎖不住臉；影片第一格才是最強的鎖。** 所以參考圖必須先調到一致，才拿去生影片。
6. **1K 場景圖裡的臉只有 100–250 px，會系統性地跑掉**：眼睛縮成小黑點、沒有亮點、鼻子變長、臉變窄。解法是 **2K 臉部設定圖（正面／3/4／側面）＋每張都附上**，以及 **「只修臉」局部重繪**（每張約 $0.07，只改 0.3–2.7% 像素，背景姿勢都不動）。
7. **風格錨點要用「人物在場景裡」的圖，不能用空景。** 用 playbill 空景當風格參考時，人物變成平面插畫；換成謝幕畫面（陶土人物站在場景裡）立刻回到立體。
8. **同一地點跨場景要互相當參考。** 四四南村黃昏版一開始畫成別的房子、101 變米色；改用白天版當參考圖才一致。
9. **色調要有錨點。** 第 13 段藍天飽和度頂到 255，影片跟著過艷；用其他場景當色調參考重生，p90 飽和度從 255 降到 191，和全片一致。用 ffmpeg 調色只能救急。
10. **重要結尾用「頭尾給圖」鎖住。** 第 13 段要求「停在兩人笑瞇眼」，只寫 prompt 不保證；給一張笑瞇眼的結尾圖，影片就一定落在那裡。
11. **「No text」模型不一定聽。** 船身、地圖、招牌、春聯都冒出亂碼字，要在檢查時抓、剪接時避。

### 3.3 生成與成本

12. **360p 草稿 → 720p 定稿的流程成立**，360p 驗過的 prompt 升 720p 沒有翻車。但只對高風險鏡頭（頭尾給圖、手部、分割裁切、微距）打草稿，其他直接 720p，省一半草稿費。
13. **附 5–6 張參考圖時，每支會多約 $0.02**（thought 與圖片輸入 token），估價要加進去。用帳本實測單價估算，誤差在 10% 內。
14. **Google AI Studio 的專案每月花費上限是另一道關卡。** 我們自己的 $8／$29 預算之外，key 本身被 AI Studio 擋過一次（HTTP 429），要事先調高。
15. **重生不一定比剪好。** 藏壽司、蛋糕店、剝皮寮、台北賓館的穿幫，都用「只取乾淨秒數」解決；真正需要重生的只有藏壽司（乾淨片段只剩 2.4 秒）和漏選的劇場鏡頭。

### 3.4 品質檢查

16. **整張圖丟給視覺模型比臉不可靠。** 有效做法：先框出臉、放大裁切，再告訴模型「已知的跑掉方式」去比對。
17. **影片穿幫要用會推理的模型看整支影片。** 實測 6 支已知答案的片子：

    | 方法 | 抓到 | 誤報 | 每支 |
    |---|---|---|---|
    | gemini-3.8-flash 預設（每秒 1 格） | 3/4，附秒數與原因 | 0 | 約 $0.008 |
    | 3.8 Flash 每秒 4 格＋中解析度 | 2/4 | 約 4 | 約 $0.015 |
    | Gemini Decision 1（高解析度） | 2/4，只有機率 | — | 約 $0.0005 |

    取樣越密不一定越好；Decision 1 不會推理，抓不到倒退走這類要比較前後格的問題。
18. **同一支跑兩次，兩次都標出的才算真的。** 17 支 ×2 只花 $0.25；真問題兩次都抓到，只出現一次的 4 個標記全是誤報或極輕微。
19. **自動檢查會漏，最後一定要人眼。** 蛋糕店桌子移位、剝皮寮「人變大但腳在往前」，模型都沒抓到，是 Clarence 看出來的。人工檢查用 0.25–0.75 秒間隔的抽格條最有效。
20. **360p 不能拿來判斷臉。** 人物小時臉只剩 60–110 px，分數一定偏低；判斷臉要看 720p。

### 3.5 剪接、配樂、字幕

21. **剪接表（EDL）是單一事實來源。** `trial-edl.yaml` 和 `mv-edl.yaml` 記下每一段的來源、進出點和原因，改剪接點只改一行再重跑。
22. **MV 要把鏡頭對到歌詞。** theplaybillv2 已有這首歌逐句對好的時間軸（`data/songs/fruit-cake-love.json`），直接沿用；歌詞內容剛好對上故事（「第一次去你家」→ 雲林老家、「成為圓滿的家人」→ 舉證書）。
23. **歌比影片長時，只取一段並在句尾淡出**（這次 0:06–1:53，「好幸福」後淡出）。
24. **字型要涵蓋日文新字體。** Noto Serif TC 少了 静騒顔増，從 Noto Serif JP 補；用 fonttools 只打包歌詞用到的字。GitHub raw 被網路擋，改從 npm 的 fontsource 取得。
25. **分割畫面用在歌詞點題的地方最有效**（「完全不同的兩人世界」）。

### 3.6 放大與輸出

26. **先放大乾淨畫面，再加字幕和音樂。** 字幕先燒進 720p 再放大會糊，Real-ESRGAN 還會把字當紋理重畫。
27. **只放大用到的片段。** 21 段在 Modal T4 平行跑 4 分 40 秒；本機 4 核 CPU 估計要 7 小時以上。改剪接點時只需重放大改動的段落。
28. **輸出一定要指定 `-pix_fmt yuv420p -profile:v high`。** 字幕＋交叉淡化的濾鏡鏈讓 ffmpeg 輸出成 yuv444p（High 4:4:4），很多播放器黑畫面。之後每次輸出都用 ffprobe 檢查格式。
29. **保留無字幕母帶**，改字幕、換語言都從它重出，不用重新放大。
30. **大檔分享**：1080p 約 80 MB，超過 GitHub 建議的 50 MB 和頁面的 16 MB 上限；審片頁放 720p 網頁版，正式分享用 YouTube 不公開或 playbill 的 R2。

## 4. 我犯的錯（避免再犯）

| 錯誤 | 影響 | 修正 |
|---|---|---|
| 探 xAI API 時送了合法請求 | 意外生成一支，花 $0.70（Omni vs Grok 階段） | 探 schema 只送無效值 |
| 臉部檢查一開始只比衣服髮型 | 12 張臉跑掉都顯示「通過」 | 改成框臉放大、列出已知跑掉方式 |
| 試片選鏡頭時漏了第 9 段劇場 | 試片少了「去看劇」的情節 | 補生成並加入剪接表 |
| 試片頁面排序程式漏掉 YouBike | 頁面少一支 | 改用剪接表順序 |
| 服裝檢查把登記日段落當便服比 | 河堤夕陽被誤判 | 有登記日服裝時只用登記日清單 |
| 輸出沒指定像素格式 | 1080p MV 在很多播放器黑畫面 | 強制 yuv420p，掃描所有檔案 |
| 第一次蛋糕店剪接點抓太寬 | 換景與蛋糕消失被留在片中 | 抽格條逐格確認後收緊 |

## 5. 下次的檢查清單

- [ ] 分鏡每一幕都確認：在地地點、人物動作、服裝、時間（白天／黃昏／夜）
- [ ] 每個角色：2K 臉部設定圖＋便服三視圖＋特殊服裝圖
- [ ] 每張參考圖：服裝檢查＋框臉檢查（分數 ≥ 4）＋人工看一遍＋飽和度和其他場景比對
- [ ] 運鏡：能固定就固定；要環繞、升起、落點時用頭尾給圖，單段 ≤ 10 秒
- [ ] 生成前：估價（含每支 +$0.02 參考圖成本）、確認 AI Studio 專案花費上限
- [ ] 生成後：3.8 Flash 預設設定跑兩次 → 人工逐格看所有落在使用片段內的標記
- [ ] 剪接：只用乾淨秒數，寫進剪接表並註明原因
- [ ] 1080p：先放大乾淨片段，再加字幕與音樂；保留無字幕母帶
- [ ] 輸出：`-pix_fmt yuv420p -profile:v high`，ffprobe 確認
